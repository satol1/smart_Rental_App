## Состояние после модернизации v5.0.2/5.0.3

### Что теперь работает по-настоящему

| Механизм | Реализация |
|---|---|
| CSRF | double-submit подписанным токеном (itsdangerous + `hmac.compare_digest`) на register/token/refresh/logout; фронт шлёт `X-CSRF-Token` и авто-перевыпускает токен при 403 (`src/lib/api.ts`) |
| Типизация JWT | claim `type` обязателен (refresh не принимается как access), алгоритм зафиксирован HS256; PyJWT вместо python-jose (CVE-2024-33663/33664) |
| Logout / denylist | `jti` refresh-токена в Redis с TTL до `exp`; fallback в память (per-process) |
| Rate limiting | slowapi: 200/мин глобально, 5/мин на auth; edge-лимит nginx `10r/m` на `/api/auth/`; real-IP через `FORWARDED_ALLOW_IPS` (uvicorn trust proxy) |
| Brute-force | 5 неудачных входов / 15 мин → блок IP 60 мин; хранение в Redis (ключ на реального клиента), Singleton-сервис |
| Пароли | bcrypt напрямую (passlib удалён — несовместим с bcrypt 4.x); политика сложности из config |
| Секреты | fail-fast при `DEBUG=false`: нет/dev-значения/короче 32 символов/менее 16 уникальных → отказ старта; генератор `scripts/generate_secrets.py`; админ-пароли только через аргумент/env/генерацию |
| Транспорт | TLS 1.2/1.3, HSTS, security-заголовки в nginx; access-токен только в памяти фронтенда, refresh — HttpOnly cookie (Secure при DEBUG=false) |
| Поверхность | БД и Redis без опубликованных портов; `/docs` и детали ошибок только при DEBUG; `/monitoring/stats` — только админ; прод-образы с HEALTHCHECK и без тестовых зависимостей; backend — non-root USER, frontend — официальная модель nginx (root-мастер + непривилегированные воркеры: мастеру нужны TLS-ключи с хост-маунта и порты 80/443) |
| Зависимости | aiohttp 3.14+, starlette 0.47+, python-multipart 0.0.20+ — известных CVE нет |

### Остаточные риски (принятые/отложенные)

- **Порт backend 8000 опубликован** в основном compose для отладки/Swagger —
  в жёстком проде уберите публикацию (nginx проксирует `/api/` внутри сети).
- **CSP nonce доходит только до API-ответов** (JSON); отдача `index.html`
  через nginx идёт без CSP-заголовка. До внедрения раздачи HTML с nonce
  механизм «висит в воздухе» для фронтенда.
- **Синхронный redis-клиент** вызывается в async-контексте (блокировки на RTT,
  до ~1 c при недоступности раз в 30 c). Отложена миграция на `redis.asyncio`.
- **In-memory fallback per-process**: при `WORKERS>1` и упавшем Redis logout на
  одном воркере не отзывает токены на другом; лимиты делятся на N. С Redis —
  не проблема; healthcheck Redis в compose настроен.
- **Refresh-токен не ротируется** (один jti на 14 дней); reuse-detection отложена.
- **Секреты на рабочей машине**: `.env` (реальные токены), `ssl/key.pem`,
  прод-дампы в `db_backup/` — вне git, но компрометация станции = компрометация
  прода. Ротация при любых подозрениях.
- Whitelist IP брутфорс-защиты хранится в памяти процесса (изменения через API
  теряются при рестарте) — хранение в Redis отложено.

## Обзор реализованных мер безопасности (исторические этапы)

### ✅ Критические исправления (завершены)

#### 1. Усиление секретных ключей
- **Скрипт генерации**: `scripts/generate_secrets.py`
- **Валидация**: Минимум 32 символа, 16 уникальных символов
- **Проверка дефолтных значений**: Блокировка запуска с дефолтными ключами
- **Использование**: `python scripts/generate_secrets.py`

#### 2. Настройка HTTPS
- **Nginx конфигурация**: Обновлена с современными SSL настройками
- **HSTS**: Включен с `max-age=31536000; includeSubDomains`
- **Дополнительные заголовки**: CORS, COEP, COOP, CORP
- **Редирект**: Автоматический редирект с HTTP на HTTPS

#### 3. Усиление политики паролей
- **Минимальная длина**: 8 символов (настраивается)
- **Требования к сложности**: Заглавные, строчные, цифры
- **Проверка на простые пароли**: Блокировка распространенных паролей
- **Валидация повторяющихся символов**: Максимум 50% повторений

### ✅ Высокие приоритеты (завершены)

#### 4. Система аудита безопасности
- **Модель**: `SecurityAuditLog` с полным логированием
- **События**: Попытки входа, подозрительная активность, доступ к данным
- **API**: `/api/admin/security/audit/*` для администрирования
- **Индексы**: Оптимизированы для быстрого поиска

#### 5. Защита от брутфорса
- **Лимит попыток**: 5 неудачных попыток за 15 минут
- **Блокировка IP**: 60 минут после превышения лимита
- **Whitelist**: Доверенные IP адреса
- **API управления**: Разблокировка, статистика, очистка

### 🔄 Средние приоритеты (в процессе)

#### 6. Улучшение CSP политики
- **Текущее состояние**: Убрано `unsafe-inline` из script-src
- **Добавлено**: `strict-dynamic`, nonces, дополнительные директивы
- **Статус**: Нонси покрыты тестами (tests/api/test_csp_nonce.py, 9 шт.); ограничение —
  nonce применяется только к API-ответам, HTML фронтенда отдаётся nginx без CSP (см. риски выше)

## 📊 Мониторинг безопасности

### API эндпоинты для админов

- `GET /api/admin/security/audit/logs` - Логи безопасности
- `GET /api/admin/security/audit/stats` - Статистика событий
- `GET /api/admin/security/brute-force/blocked-ips` - Заблокированные IP
- `POST /api/admin/security/brute-force/unblock/{ip}` - Разблокировка IP
- `GET /api/admin/security/health` - Состояние системы безопасности

### Типы событий безопасности

- `login_success` / `login_failed` - Попытки входа
- `brute_force_attempt` - Попытки брутфорса
- `suspicious_activity` - Подозрительная активность
- `data_access` - Доступ к данным

### Уровни серьезности

- `low` - Обычные события (успешные входы, доступ к данным)
- `medium` - Неудачные попытки входа
- `high` - Подозрительная активность
- `critical` - Брутфорс атаки, попытки обхода защиты
