# tests/attic/api-legacy — устаревшие API-тесты

Перенесено сюда 08.09.2026 из `tests/api/` в ходе пост-аудиторской стабилизации.

## Почему

Эти 33 файла (~364 теста) написаны под **устаревший контракт API** и были
красными задолго до модернизации 2026-09 (проверено: те же 364 падения
воспроизводятся и на рабочем дереве до правок, и в Docker full-architecture
стеке). Типичные расхождения с текущим API:

- тесты ждут списки в ответе, а эндпоинты отдают `{items, total}` (пагинация);
- тесты обращаются к маршрутам, которых больше нет (`PUT /api/user/profile` и др.);
- переопределение зависимостей через `app.container.<service>.override(...)`
  для провайдеров, которых больше нет в DI-контейнере (AttributeError);
- патч `api.dependencies.get_current_user` больше не влияет на авторизацию
  (401 вместо 200) — Depends перешёл на `Provide[...]`/permissions-слой.

Держать их в рабочем наборе нельзя: полный стек (full-architecture) падал
на фазе `pytest tests/api/` и из-за `&&`-цепочки не доходил до
integration/e2e/critical фаз; CI backend-джоба падала по той же причине.

## Что вместо них

Актуальный контракт API покрыт:

- `tests/api/` — оставлены только живые наборы: `test_auth_api.py`,
  `test_csrf_protection.py`, `test_rate_limiting.py`, `test_csp_nonce.py`;
- `tests/integration/` — реальные сценарии через БД;
- `tests/e2e/` — полный жизненный цикл резерв→аренда→возврат через HTTP;
- `tests/critical/` — критические эндпоинты.

## Если понадобится оживить

Файлы не удалены. Для восстановления: перенести обратно в `tests/api/` и
привести ассерты к текущему контракту (пагинация `{items,total}`, актуальные
маршруты в `api/router.py`, переопределение DI через
`app.container.<актуальный провайдер>.override(...)`).
