### 🔴 Критические (деньги)
- **Лимиты промокодов не работали никогда**: `record_promo_code_usage` не вызывался ни из одного потока — `times_used`/`max_uses_per_user` оставались нулями, промокод можно было применять бесконечно. Теперь запись/снятие использования встроены в создание/отмену резерва, создание/удаление аренды с нуля, смену промокода; инкремент атомарный (`UPDATE ... SET times_used = times_used + 1`), отмена резерва освобождает лимит
- **Уменьшение предоплаты начисляло деньги из воздуха**: при `difference < 0` писалась положительная транзакция BALANCE_TOP_UP вместо зеркального списания → баланс рос при уменьшении предоплаты. Теперь отрицательное списание PREPAYMENT_REFUND_ON_REVERT с привязкой к аренде
- **`actual_return_date` без границ**: дата раньше начала аренды давала кредит больше списанного, будущая — завышенный штраф. Введена валидация (422): не раньше start_date; просрочка не регистрируется заранее (дата позже end_date и позже сегодня); «возврат по плану» в плановую дату разрешён + кредит ограничен стоимостью аренды

### 🟠 Высокие
- **Изменение `end_date` активной аренды не проверяло занятость и не двигало баланс**: продление могло создать овербукинг, а дельта стоимости не отражалась на балансе. Теперь advisory-лок + проверка конфликтов (исключая саму аренду) + транзакция дельты (доплата/возврат)
- **Аренда с нуля не валидировала диапазон дат**: `end < start` создавала аренду с нулевой стоимостью → добавлены validate_date_range и запрет прошлой даты начала
- **PUT-обновление резерва молча стирало промокод** (поле не прислали → скидка обнулялась, цена росла) → не присланное поле сохраняет действующий промокод; смена промокода пересчитывает лимиты использований
- **Grace-период отмены резерва (главный UX-дефект)**: правило «≤2 дня до начала нельзя отменить» действовало с первой секунды — ошибившийся с датами пользователь попадал в ловушку («создать можно, отменить нельзя»). Введён grace-период 24 ч после создания: отмена/редактирование разрешены независимо от близости даты; правила и сообщения синхронизированы фронт↔бэк (`RESERVATION_GRACE_PERIOD_HOURS`)
- **Асимметрия окна редактирования**: редактирование проверялось только по старой дате — «далёкий» резерв можно было передвинуть на завтра в обход правила → проверяются обе даты

## Hotfix 5.0.2 - 08.09.2026 — Пост-аудиторская стабилизация (5 агентов аудита «чистым взглядом»)

Полный аудит всех модулей (auth/security, цепочка резерв→аренда→возврат, финансы, фронтенд/UX, инфраструктура/тесты) + исправления.

### 🔴 Критические
- **Возврат аренды падал с 500**: в ветке случайно был удалён `self` из сигнатуры `_calculate_return_adjustments` — каждый `POST /admin/rentals/{id}/return` давал TypeError. Восстановлен; проверено живым smoke-тестом
- **Двойной возврат аренды** создавал повторные денежные транзакции (штраф/кредит) и перезаписывал `final_cost`: добавлен guard «уже возвращена» → 409 (`OrderValidator.validate_rental_is_returnable`)
- **Прод-nginx ломал всю авторизацию**: `proxy_pass http://backend/api/` в `location /api/auth/` переписывал `/api/auth/token` → `/api/token` (404 в проде, в dev работало). Исправлен на `proxy_pass http://backend;`
- **Все Docker-тест-раннеры не работали**: hardened-образ (non-root) + `pip install` в test-backend → Permission denied. В 5 тестовых compose добавлен `user: root` (тестовые контейнеры, прод не затронут)

### 🟠 Высокие
- **CSRF ломал refresh и logout**: `baseApi` не отправлял `X-CSRF-Token` → через 60 мин все пользователи разлогинивались, серверный logout (и denylist refresh-токенов) был недостижим. Добавлен CSRF-интерцептор + перевыпуск токена и повтор запроса при 403-CSRF (`src/lib/api.ts`)
- **Общий IP за nginx**: без `FORWARDED_ALLOW_IPS` uvicorn видел всех клиентов как IP nginx-контейнера → лимиты 5/мин и brute-force действовали на весь сайт суммарно. Добавлено в оба compose; проверено: счётчик теперь на реальном клиенте
- **Rate limiter ронял приложение при отказе Redis в рантайме** (slowapi 500 на каждый запрос): limiter переведён на `memory://` (per-worker; edge-лимит в nginx сохранён)
- **In-memory fallback brute-force не работал**: сервис был `Factory` (пустые счётчики на каждый запрос) → `Singleton`
- **Race баланса (lost update)**: `skip_locked=True` + fallback «продолжить без блокировки» → убраны; обычный `FOR UPDATE` ждёт строку
- **Удаление аренды из резерва теряло деньги клиента** и оставляло резерв «мертвым» (fulfilled без аренды): DELETE для from-reservation аренд теперь 409 с подсказкой использовать revert
- **Промокод с min_order_amount ломал создание аренды с нуля** (валидация по сумме 0): двухпроходный расчёт как в резервах
- **Тупик редактирования резерва**: `confirm_date_adjustment` (подтверждение даты-выходного) игнорировался бэкендом → вечный 409-цикл. Флаг прокинут в оба update-метода
- **Конвертация просроченного резерва** создавала аренду с end<start и нулевой стоимостью → 409
- **Конвертация не проверяла доступность** (аренда с today расширяется назад до start_date резерва) → добавлена проверка с исключением собственного резерва
- **Гонка двойного бронирования**: проверка доступности была обычным SELECT → добавлены `pg_advisory_xact_lock` по equipment_id (сортировка против дедлоков)
- **Кап скидки 75% не известен фронту**: карточки показывали цену ниже фактической → `MAX_COMBINED_DISCOUNT_PERCENT=75` в `src/constants/discount.ts`, применён во всех точках расчёта
- **CI падал**: ruff не устанавливался (добавлен в requirements-test.txt); DB-тесты без маркеров собирались в прогоне без БД (pytestmark добавлен)
- **Битые скрипты тестов**: ссылки на несуществующие compose-файлы; `run_e2e_tests -d` валил рабочий стек и падал на non-root pip — переписаны на изолированные стеки

## Hotfix 5.0.1 - 08.09.2026 — Белая страница в прод-сборке

- **Причина**: циклическая зависимость чанков после code splitting — `react-vendor` импортировал общий модуль из чанка `admin`, тот в свою очередь импортировал `react-vendor`; при старте React оказывался неинициализирован → `TypeError: Cannot read properties of undefined (reading 'createContext')` → белая страница

Импорт-граф проверен: ациклический
- **Бонус-фикс**: `nginx.dev.conf` писал логи в файлы — фатально для non-root контейнера (рестарт-луп); переведён на stdout/stderr
- Проверено в реальном браузере: главная/`/how-it-works`/`/rules` рендерятся, тёмная тема применяется (класс `dark` до бандла через inline-скрипт), стек healthy

## Версия 5.0 - 07.09.2026 — Модернизация платформы

### 🔐 Безопасность (критические исправления аудита)
- **CSRF-защита включена по-настоящему**: убраны `try/except: pass` в auth-эндпоинтах; валидация double-submit + подписи itsdangerous (контракт фронтенда сохранён; `DISABLE_CSRF` остался для тестовых окружений)
- **Rate limiting работает**: SlowAPIMiddleware (200/мин глобально) + 5/мин на login/register/refresh; nginx `limit_req` на `/api/auth/`
- **JWT type safety**: refresh-токен больше не работает как access; jti + denylist при logout (Redis с fallback)
- **Секреты**: дефолтные значения удалены из кода; прод-старт без секретов — fail-fast с перечнем; пароли админ-скриптов — env/CLI/генерация
- **Зависимости**: python-jose → PyJWT (CVE-2024-33663/33664 закрыты), aiohttp 3.9.1 → 3.14.3, passlib → bcrypt напрямую (совместимость старых хешей покрыта тестом)
