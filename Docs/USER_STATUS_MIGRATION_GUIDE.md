# Руководство по миграции статусов пользователей

## 📋 Описание

Это руководство описывает процесс миграции статусов пользователей для внедрения градации статусов с различными правами на создание, редактирование и отмену резервов.

## ⚠️ Важно перед миграцией

1. **Создайте резервную копию базы данных** перед выполнением миграции:
   ```bash
   docker-compose exec db pg_dump -U ${POSTGRES_USER} -d ${POSTGRES_DB} > backup_before_migration_$(date +%Y%m%d_%H%M%S).sql
   ```

2. **Убедитесь, что контейнеры запущены**:
   ```bash
   docker-compose up -d
   ```

3. **Проверьте подключение к базе данных**:
   ```bash
   docker-compose exec db pg_isready -U ${POSTGRES_USER}
   ```

## 🚀 Выполнение миграции

### Вариант 1: Использование готовых скриптов (рекомендуется)

#### Для Linux/macOS:
```bash
chmod +x scripts/migrate_user_statuses.sh
./scripts/migrate_user_statuses.sh
```

#### Для Windows:
```cmd
scripts\migrate_user_statuses.bat
```

### Вариант 2: Ручное выполнение команд

#### 1. Применить миграции БД (если нужно):
```bash
docker-compose exec backend alembic upgrade head
```

#### 2. Выполнить миграцию данных:
```bash
docker-compose exec backend python scripts/migrate_user_statuses.py
```

## 📊 Что делает миграция

Миграция выполняет следующие действия:

1. **Миграция старых статусов:**
   - "Активный" → "Новый"
   - "Требует подтверждения" → "Новый"
   - "Заблокирован" → остается "Заблокирован" (если есть просроченные резервы)

2. **Пересчет статусов по количеству успешных аренд:**
   - ≥7 завершенных аренд → "VIP"
   - ≥3 завершенных аренд → "Постоянный"
   - Иначе → "Новый"

3. **Проверка просроченных резервов:**
   - Если у пользователя ≥3 просроченных резервов → устанавливается "Заблокирован"

4. **Сохранение специальных статусов:**
   - "Персона НонГрата" не изменяется автоматически

## 📈 Статистика миграции

После выполнения миграции вы увидите статистику:
- Количество пользователей, мигрированных в "Новый"
- Количество пользователей, мигрированных в "Постоянный"
- Количество пользователей, мигрированных в "VIP"
- Количество пользователей, заблокированных из-за просрочек
- Количество пользователей без изменений
- Количество ошибок (если были)

## 🔍 Проверка результатов

После миграции можно проверить результаты:

```bash
# Подключиться к базе данных
docker-compose exec db psql -U ${POSTGRES_USER} -d ${POSTGRES_DB}

# Проверить распределение статусов
SELECT status, COUNT(*) as count 
FROM users 
GROUP BY status 
ORDER BY count DESC;
```

## ⚠️ Возможные проблемы и решения

### Проблема: "Контейнер backend не запущен"
**Решение:** Запустите контейнеры:
```bash
docker-compose up -d
```

### Проблема: "База данных не готова"
**Решение:** Подождите несколько секунд и повторите попытку:
```bash
sleep 5
docker-compose exec backend python scripts/migrate_user_statuses.py
```

### Проблема: "Ошибка импорта модулей"
**Решение:** Убедитесь, что скрипты скопированы в контейнер:
```bash
docker-compose restart backend
```

### Проблема: "Ошибка подключения к базе данных"
**Решение:** Проверьте переменные окружения в `.env` файле:
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_DB`
- `DATABASE_URL`

## 🔄 Откат миграции

Если нужно откатить миграцию, используйте резервную копию:

```bash
# Остановить контейнеры
docker-compose down

# Восстановить из резервной копии
docker-compose exec -T db psql -U ${POSTGRES_USER} -d ${POSTGRES_DB} < backup_before_migration_YYYYMMDD_HHMMSS.sql

# Запустить контейнеры
docker-compose up -d
```

## 📝 Логи

Все логи миграции выводятся в консоль. Для сохранения логов в файл:

```bash
./scripts/migrate_user_statuses.sh 2>&1 | tee migration_log_$(date +%Y%m%d_%H%M%S).txt
```
