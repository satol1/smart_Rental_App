# План по улучшению frontend-приложения

## Этап 1: Исправление критических архитектурных ошибок (Безопасность и Сессии)
1. Отключить взаимосвязь `cookieConsent` и `withCredentials` в `api.ts`.
   - В `axios.create` жестко прописать `withCredentials: true`.
   - Удалить проверку `!hasCookieConsent()` из логики interceptor'ов, отвечающих за CSRF и Refresh. CSRF и Refresh должны работать до согласия на маркетинговые Cookie-файлы.
   - Использовать базовые axios-запросы (или чистый axios) для endpoints `/auth/refresh` и `/auth/csrf-token`, чтобы изолировать их от interceptors основного `api`.

## Этап 2: Унификация стейт-менеджмента для Авторизации (Рефакторинг кода)
1. Оставить `AuthService` как слой взаимодействия с API, а управление состоянием форм и приложения перенести/унифицировать в `authStore` и `useAuthFormViewModel`. Устранить дублирование API запросов.
2. Синхронизировать очистку пользователя при 401 ошибках.

## Этап 3: Починка Zod Схем и Улучшение Валидации
1. Переписать валидатор номера телефона в `validationSchemas.ts`: `/^[78]\d{10}$/`.
2. Улучшить `equipmentUpdateExtendedSchema` и другие схемы.

## Этап 4: Настройка роутинга и улучшение UX 
1. Создать компонент `NotFoundPage.tsx` (Страница 404) и добавить в `Routes` внутри `App.tsx`: `<Route path="*" element={<NotFoundPage />} />`
2. Создать страницу `ForbiddenPage.tsx` (Ошибка 403) и добавить роут для нее.
3. Отрефакторить `RequireAuth.tsx` для редиректа на `/forbidden` при отсутствии нужной роли (а не на `/`).
